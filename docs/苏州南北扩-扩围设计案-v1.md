> 起草：游有方（创意总监）｜依据：team-lead 已冻结网格（选项 A 苏州南北全并）
> 口径：所有坐标写**真实 lat/lon**，由 `data_sz.js` 头部的 `ll()/poly()/at()` 按 `CM.GEOS.sz.proj` 现场换算，**不写格坐标**。本文件只做设计文档，不改 `data_sz.js` 本身。

## 0. 冻结网格（已锁定，直接用）

```
bbox [S, W, N, E] = [30.8400, 120.4150, 31.9300, 121.0680]
proj = { lon0: 120.415, lat0: 31.93, kx: 381.32, ky: 447.71 }
W = 249, H = 488 → 121512 格，每格 ≈249 m
```
- 北界 31.501 → 31.93（常熟 31.50–31.68、张家港 31.78–31.92 在图内）
- 南界 31.00 → 30.84（盛泽 30.86–30.95 在图内）
- 现有苏州主城 regions/centers/landmarks 全用 lat/lon，`proj` 变化对它们透明；本设计**只新增**三块，不碰现有条目。
- geo 已重编码：admin 关系 44 → 166、places 561 → 2275，region 的 `district` 匹配与地标 `at()` 可对照真实 OSM 名（本设计统一用 `poly` 显式圈定，确定性最强，避免 admin 名匹配失败）。

## 1. 落码注意事项（必读）

1. **北界裁剪（金港/香山/双山岛）**：bbox 北界 `N=31.93`。张家港**金港镇/保税区（~31.95N）、香山（~31.95N）、双山岛（~32.0N）已在图外**。本设计 `zjg_port` 只圈其南缘（lat ≤31.93），`landmarks` 里**舍去双山岛**、香山取 31.925 贴边落点。若需完整港区，北界需抬到 ~31.97（对应 H≈500、约 124500 格）。
2. **文件头注释过期**：`data_sz.js` 顶部注释（约 9–11 行）仍写旧 bbox `31.000/120.415/31.501/121.068` 与 `lat0:31.501`，实现时同步改为 `30.840/120.415/31.930/121.068`、`lat0:31.93, ky:447.71`，否则误导后续维护。
3. **`simRoads` 格坐标已偏移**：`simRoads[0].p = [[8,40],[40,40],[64,40]]` 是旧 `lat0=31.501` 下的格坐标；`lat0` 抬到 31.93 后这些 y 对应纬度变了约 40 格 → 需按新 proj 重算（可用 `ll()` 反向；或暂不改，因其为 2030 后虚构规划路）。**全图任何硬编码格坐标都需重核**。
4. **地标落陆地校验**：常熟站/张家港站/香山/港区等贴近长江南岸，落码前用 `probe-cell`（仓库既有工具）按 landFrac 复核，仿现有「苏州奥体/国博中心」做法——若落到水面则向最近陆地平移，避免被静默丢弃。
5. **`region.pop` 是早开阈值**：`game.js:228` 当 `tot.pop ≥ rg.pop` 时该区可**提前**于 `open` 年开放。下表 `pop` 故意设在对应 `open` 年附近的城市总人口（7.6e6/8.6e6/9.4e6），使北/南三块随城市增长到规模后递进解锁，不抢跑。

## 8. 已知风险 / 待 team-lead 确认

1. 北界 31.93 裁掉张家港**金港/保税区北区、香山、双山岛**——若设计上必须含完整港区，需抬北界至 ~31.97（H≈500、约 124500 格），并同步重抓/重投影 geo。
2. `defaultRegion.name` 仍写「外围（昆山·常熟·太湖方向）」，现常熟/张家港已为具名区域，标签可简化为「外围（太湖·长江方向）」（非阻塞）。
3. 新增区 `open` 年份为**模拟推演值**（苏州市域轨交真实未到常熟/张家港），属 `dataNote` 的 `sim` 范畴；若希望更保守，可把 changshu/zjg 的 open 推到 2045/2050 或以 `open: null`（永不开放，仅作背景城）。
